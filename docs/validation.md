# 双端验证记录

日期：2026-11-07。

## 当前 Windows OCR 工具

### 1.1.0：识别历史栏目

主窗口右侧新增“识别历史”：稳定识别结果按时间倒序记录，最多 20 条，最新显示在最上面；点击记录在左侧卡片区查看完整属性，选择选区或再次开始识别可返回实时视图。历史按选区合并，同一选区连续识别同一物种不重复新增；只保存编号、选区名称和本地时间，不保存原始 OCR 文字。数据保存在 `%LOCALAPPDATA%\PokeMMOHint\recognition-history.txt`，缺失或损坏时忽略，不影响识别。

新增 6 项历史单元测试（倒序与上限、按选区合并、格式往返、损坏行忽略、无效输入），共 35 项核心测试通过；Windows 适配层 Clippy 通过。本机 Windows 在 125% 缩放下实际启动 EXE，以临时用户目录预置历史文件，确认列表倒序、空状态提示和点击记录查看详情；未运行 OCR，真实识别写入及超过 20 条后的轮换仍需用游戏画面验证。

### 0.6.0：白字提取、模型字表检查及可选 Windows OCR

用户截图中猫鼬斩在灰度／二值化下被误读。新增白字通道：提取明亮低色差像素，丢弃彩色背景与暗色阴影，转换为白底黑字后 4 倍放大；白色背景占比过高则跳过。图像测试覆盖背景颜色排除、白色笔画保留和白底面板跳过。

读取实际固定模型的 LSTM unicharset，确认 38 个名字用字缺失，影响 57 个物种，包括“鼬”。对截图三个裁剪的灰度、白字、二值化均执行 Linux Tesseract C API；原模型仍无法输出“猫鼬斩”，不伪称白字处理已经修复该样例。完整结果在 [猫鼬斩回归](evidence/ocr-zangoose-regression.json) 与 [模型覆盖](evidence/ocr-model-coverage.json)。

识别失败且含可能的中文文字时，可通过无控制台的内嵌 PowerShell 脚本尝试 Windows.Media.Ocr，要求已有简体中文 OCR 语言，不自动安装、不联网。所有读法沿用名字／编号交叉验证、冲突拒绝和两帧稳定规则。备用引擎失败后本轮停止重试，超大图片只跳过对应选区；候选涉及模型缺字时展示实际缺字与确认／编号方案。Windows 系统备用引擎未在本环境执行，需用户本机验证。

### 0.5.1：发行版无附加控制台窗口

用户截图确认发行版主界面旁存在黑色终端。主 EXE 改为 `windows_subsystem = "windows"`，正常 GUI 启动失败使用原生错误对话框；OCR 子进程原有 `CREATE_NO_WINDOW` 保留。移除发行 `Start.cmd` 模板，用户直接启动 EXE，避免批处理终端等待主界面退出。

发版脚本同时验证 x64 PE 的 GUI 子系统，使用 `.NET Process` 的显式输出重定向、无控制台创建和等待退出执行 GUI EXE 的 CLI 自检，保留退出码、输出、超时和 OCR 结果校验。20 项核心测试与 Windows 适配层 Clippy 通过；当前环境未执行新 Windows GUI 或 PowerShell 发版，实际控制台消失需重新打包后在 Windows 验证。

### 0.5.0：通用屏幕 OCR，无游戏进程依赖

删除 `EnumWindows`、`GetWindowThreadProcessId`、`OpenProcess`、`QueryFullProcessImageNameW` 及 PokeMMO 可执行文件名匹配。框选、编辑、抓屏与标签改为虚拟桌面坐标；不再要求游戏启动或位于前台。按钮提示只判断辅助程序自身是否处于前台。

配置另存 `screen-regions.txt`，保存每个选区相对虚拟桌面的偏移、屏幕原点和尺寸，支持负坐标副屏；显示器布局变化时拒绝沿用。旧窗口坐标配置保留，首次升级需重新框选，并尽量沿用旧主窗口位置。屏幕选区固定，移动目标窗口后需手动调整。适用于任意可见来源，物种／形态／世代规则的原数据限制仍保留。

20 项核心测试及严格 Windows 适配层 Clippy 检查通过；新增验证负原点屏幕转换、屏幕配置往返、布局变化拒绝及坐标溢出保护。Windows 模拟器／其他游戏实机框选和浮窗仍需用户本机验收。

### 发版修复：DLL 名称中的加号

用户实测发版脚本在 `libstdc++-6.dll` 被名称校验误拒绝。已在 PE 导入名称允许字符中加入 `+`，保留文件名和扩展名限制；使用独立 objdump 遍历本机 Tesseract 的所有递归 DLL 导入，全部名称通过修正规则，路径形式和非 DLL 扩展名仍拒绝。该检查验证名称规则，不代表已执行完整 Windows 发版。

### 0.4.2：便携发行内置 Tesseract

按用户要求将发行包改为内置 Tesseract EXE、递归依赖 DLL 和中文模型。`scripts/ocr_runtime.ps1` 解析 x64 PE 普通与延迟导入，缺少非系统依赖即报错。发版脚本保留来源运行目录许可材料，记录运行文件与版本哈希；解压后检查闭合依赖，并使用包内环境执行生成图片的 OCR 自检。用户启动脚本不再调用安装器、winget 或 PowerShell；应用优先使用相邻 OCR 目录。删除旧发行安装脚本。

19 项核心测试和 Windows 适配层 Clippy 通过。独立 objdump 核对得到 27 个运行文件，递归依赖均可由该目录和 Windows 系统库满足；引擎＋模型的临时 ZIP 样例压缩为 39,028,728 字节，解压哈希全部吻合。Linux Tesseract C API 使用 Windows Arial Bold 字体生成的测试图片，实际读出 `No.573`。证据见 [运行文件核对](evidence/portable-ocr-runtime.json) 和 [发行输入检查](evidence/release-input-validation.json)。这些不是新版 Windows 应用的运行验收；实际便携包及 Windows OCR 自检仍需在发布者本机执行。下方轻量发版记录为历史行为，已被本版替代。

### 仓库清理与轻量发行脚本

删除旧 Mod 资源、`.mod` 测试包、构建／UIA 探针脚本及对应调查文档；保留 OCR 程序、数据导入／核对、图标和相关证据。增加 `.gitignore`、行尾配置、Windows PowerShell 发版脚本、用户启动／引擎安装脚本和用户说明。轻量包只带模型，由首次启动安装 Tesseract 引擎，不复制本机全部 DLL。模型 SHA-256 固定，脚本按 Cargo 版本号测试、编译、压缩、解压校验并生成发布校验值。

当前环境不能启动 Windows PowerShell，未在这里实际执行发版脚本，也未生成新版 ZIP。脚本里的 Windows 构建、EXE 自检和解压校验在发布者执行时完成。Git 忽略规则和打包输入清单在本环境核对；没有初始化或修改当前只读 Git 目录。

### 0.4.1：按钮文字提示与五 ROM 覆盖核对

按钮悬停文字改为应用绘制的无激活透明浮窗，使用现有 150ms 定时器检测，停留约 300ms 后显示当前原生按钮文字。兼容不同公共控件版本，开始／暂停与候选确认动态同步；不截获鼠标，移开、失焦或最小化后隐藏。此改动通过 Windows 适配层 Clippy／类型检查；真实鼠标交互仍需 Windows 验证。

新增只读核对脚本 `scripts/audit_ocr_coverage.py`，实际解析五个本机 ROM 的 personal/base-stats 表，核对全国编号、基础属性和中文字符串。火红／绿宝石各 386 种，心金／白金各 493 种，黑白 649 种；并集 649，与现有数据的缺号和属性差异均为零。完整记录见 [species-coverage-audit.json](evidence/species-coverage-audit.json)。内部额外槽位为占位或形态，不扩张全国编号；形态独立查询仍未实现，不宣称所有基础物种都能在游戏中捕获。

### 0.4.0：统一图标按钮与选区拖动编辑

标题去掉“OCR 试用版”，开始／暂停按钮移至最左。所有应用按钮改为同一张 imagegen 生成九宫格拆分出的图标，保留原按钮名称用于可访问性，并增加原生悬停提示。保存名称左侧新增选区调整按钮：高亮当前框，拖动内部移动、边缘或角缩放，Enter 保存、Esc 取消，编辑后恢复此前扫描状态。

19 项核心测试和 Windows 适配层严格 Clippy 检查通过；新增验证移动／缩放坐标限制、最小尺寸、无变化拖动。图标资源打包为 10 个图标组（应用图标加 9 个按钮图标），全部嵌入 EXE。Windows 原生悬停提示、编辑器实际拖动与图标显示仍需本机重新编译验收。

### 0.3.1：自定义选区名称与生成图标

选区下拉框改为可编辑，点击“保存名称”后持久化，最多 32 字，空白恢复默认名称；配置 v2 兼容 v1 和旧单选区。重命名不重启 OCR，删除／清空同步处理名称。18 项核心测试及 Windows 适配层 Clippy 通过，新增名称往返、旧配置默认名称、标点保留、空白恢复及非法名称验证。

使用内置 imagegen 绘制透明图标，原图、ICO 和提示词均已保存在 `windows-ocr/assets/`。ICO 包含 7 个尺寸，构建脚本生成 RT_ICON／RT_GROUP_ICON，MSVC 链接时嵌入 EXE。开发环境用 Rust 自带 LLD 将资源成功链接为临时 Windows PE，并检查资源表中 7 张图标和 1 个图标组；这验证资源打包，不等于应用已在 Windows 运行。标题栏、任务栏和资源管理器显示仍需本机验收。

### 0.3.0：多选区持续识别与悬停标签

新增最多 16 个选区的独立连续识别，最多两个 OCR 工作线程；每个稳定结果在选区上方显示首个弱点，悬停展开复用的完整卡片。浮动窗口不激活、不抢游戏焦点。工具栏移除重复的定位、最小化按钮，增加选区列表、删除和清空。配置保存多个客户区坐标和主窗口位置，兼容旧版单选区文件。浮窗位置优先避开 OCR 选区，被遮挡位置暂缓读取，15 秒未更新清除旧结果。

17 项核心测试通过；`cargo clippy --offline --all-targets --features windows-check -- -D warnings` 通过。新增覆盖多选区配置往返、旧格式迁移、清空保存、数量／坐标限制、负屏幕坐标、标签位置、首个弱点与各选区独立持续更新。

### 0.2.0：窗口与识别改进

用户截图确认旧版本已在 Windows 运行，但有“君主蛇”误识别为“君主尼”的问题。新版改为卡片和倍率标签，增加显式最小化、标准标题栏与任务栏入口，删除结果末尾说明。预处理改为保留灰度的 4 倍双线性放大和白边，未匹配时使用二值化备用通道，并向引擎提供物种词表。单字近似仅提供唯一候选按钮，需要用户确认；不自动猜物种。
