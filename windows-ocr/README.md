# Windows OCR 属性提示（Rust 1.2.0）

这是独立 Windows 程序，不是 `.mod` 包。直接截取用户框选的屏幕区域，无需检测 PokeMMO 进程；可用于模拟器、其他宝可梦游戏或图鉴页面，物种及相克规则需在现有数据范围内。Rust 原生窗口、截图和属性匹配不依赖第三方 Rust crate；OCR 可选 Windows 系统中文识别或 PP-OCRv6 tiny。应用运行时本地识别，不发送截图或查询到云端。

0.7.0 新增引擎设置与按需下载，支持多个选区持续识别，每个成功匹配的选区上方显示独立的弱点小标签，鼠标悬停展开完整信息卡。选区和主窗口位置自动保存。用户已确认前版卡片界面改善；新版已通过核心测试和 Windows 适配层静态检查，本环境不能启动 Windows EXE，**多选区与浮动标签需要本机重新编译验证**。

1.1.0 在主窗口右侧新增“识别历史”栏目：每次稳定识别后按时间倒序记录，最新的显示在最上面，最多保留 20 条；点击任一记录，左侧卡片区显示该物种的完整属性，选择选区或开始识别可返回实时视图。历史按选区合并，同一选区连续识别同一物种只记一条；只保存物种编号、选区名称和本地时间，不保存原始 OCR 文字。重启后自动恢复。

1.2.0 支持中文、English、日本語三种界面与游戏识别语言，设置中分开选择：界面语言控制窗口、卡片、类型名称和识别历史；游戏语言决定 Windows OCR 的识别语言与物种名匹配。英文/日文物种名来自 PokeAPI 公开的官方译名数据，生成 649 条本地表，运行时不联网；中文数据保持原有 ROM 来源。PP-OCRv6 tiny 的字表不含假名，日文名只能使用 Windows 日文 OCR 或 No.编号，英文可继续使用两种引擎。候选确认按游戏语言分别记忆。

## 更新已有版本

先退出旧程序，再在项目目录运行：

```powershell
cargo run --release --manifest-path .\windows-ocr\Cargo.toml --offline
```

无需重新安装引擎或下载已准备好的模型。之后可以继续使用 `run.cmd` 启动。

0.4.1 将按钮提示改为应用自行绘制的置顶文字浮窗，移开鼠标、切换应用或最小化后隐藏；开始／暂停和候选确认会显示当前文字。提示不依赖 Windows 公共控件版本，不拦截鼠标操作。

完整结果继续采用编号／名字、属性、弱点、普通伤害（1倍）、抗性、免疫的分区卡片。标题栏显示“PokeMMO 属性提示”。应用按钮均采用蓝金色生成图标，鼠标悬停约 0.3 秒显示当前按钮的文字提示，键盘聚焦仍保留原功能名称。第一排从左到右为开始／暂停、添加选区、删除当前选区、清空选区。

选区下拉框可以直接编辑名称，点击旁边软盘图标“保存名称”生效并自动保存；最多 32 个字，留空恢复默认名称。重命名不会中断识别。

保存图标左侧的“四向箭头选框”用于查看和调整当前选区：当前选区高亮，其他适用选区显示为灰色参考框。拖动框内移动位置，拖动边缘／角调整大小；Enter 保存，Esc 取消。修改期间暂停 OCR，关闭编辑器后恢复此前识别状态，名称不变。拖动限制在当前虚拟桌面范围内，最小 8×8 像素；支持副屏的负坐标。显示器布局或屏幕分辨率改变后，需要重新添加适用选区。

点击开始识别，启动成功后主窗口自动最小化，失败则保留窗口显示原因；恢复后可以暂停或修改设置。标准标题栏的最小化仍可使用，最小化不暂停识别。

## 源码开发首次启动

在 Windows PowerShell 中运行：

```powershell
cd D:\codes\tools\pokemmo-mod
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\windows-ocr\setup.ps1
```

脚本检查 Windows Cargo，运行测试、编译并启动窗口，不安装 Tesseract 或下载模型。点击工具栏齿轮进入设置，选择识别引擎：

- **Windows 中文 OCR（默认）**：调用系统已安装的简体中文识别功能，不携带模型。若未安装，点击语言设置按钮，在简体中文语言选项中安装“光学字符识别”，然后重试；安装由 Windows 完成，可能需要管理员权限。
- **PP-OCRv6 tiny**：选择后自动下载模型与推理组件，显示进度。成功后点击对勾应用，取消可保留已完成的缓存下载。模型约 4.46 MB，推理组件下载约 17 MB，解压占用另计；不应将模型大小当作完整引擎大小。默认 HF 镜像优先，可切换官方源；原生推理组件从 Microsoft 官方 NuGet 固定版本下载，执行时使用 CPU。

设置与下载保存在 `%LOCALAPPDATA%\PokeMMOHint\`，引擎偏好为 `ocr-settings.txt`，PP-OCR 文件位于 `ocr\ppocrv6-tiny-9ef676d6\`。下载完成后可离线使用，更新应用不需要重新下载。再次打开设置或切换下载源时，已就绪缓存直接本地加载，不启动下载脚本；界面明确显示“已复用本地缓存，未下载文件”。缓存加载失败先提示错误，点击重试才进入文件检查和修复。模型 SHA-256 固定核对；运行组件下载后记录并复核各 DLL 哈希，准备阶段还会启动隔离子进程，实际加载模型并验证输出格式。失败可重试或切换引擎，准备成功才允许应用。HF 镜像失败会尝试官方源，反之亦然。

如果报 `link.exe` 或 Windows SDK 缺失，需要 Visual Studio 的“使用 C++ 的桌面开发”构建工具；仅安装 Rust 不保证 MSVC 链接环境齐全。脚本不会自动安装 Visual Studio。

之后双击 `windows-ocr/run.cmd` 即可启动。输出程序为 `windows-ocr/target/release/pokemmo-hint.exe`。

## 使用

1. 打开任意游戏、模拟器或图鉴页面，让中文物种名／编号在屏幕上可见。无需启动 PokeMMO。如果还在使用旧物种名修改 Mod，应先禁用以避免文字污染。
2. 点击“添加选区”，拖框选择一只敌人的名字那一行；可以包含等级和性别，尽量排除血条。Esc 取消。可在不同战斗布局分别添加，最多保存 16 个选区，每个选区只框一只宝可梦。
3. 可以继续添加群怪各名字的位置、单人／玩家对战位置，或图鉴的 `No.573 奇诺栗鼠` 标题位置。支持 `No.573`、`No. 573`、`#573` 和全角字符。没有有效文字的选区不显示标签。
4. 点击“开始识别”，切回游戏。每个选区独立轮询，两次连续结果一致后，在该选区上方显示**第一个弱点**，例如 `岩石×4`；没有属性弱点时显示“无弱点”。成功后继续识别，换敌人会更新。
5. 鼠标悬停任一小标签，展开该敌人的完整卡片，显示名字、编号、属性、全部弱点、普通伤害属性、抗性与免疫。鼠标可以移入卡片查看，离开后自动收起；浮窗不抢游戏焦点。普通伤害采用灰色标签，较多时自动换行；悬浮详情及主窗口卡片按内容调整高度，避免截断。缩略标签和悬浮详情均采用带三角尖的气泡，尖角指向对应名字选区；屏幕顶部放不下标签时改放选区旁边，尖角方向随位置调整，并在圆角附近留出间距。
6. 主窗口下拉列表可切换查看某一选区的识别状态，支持删除当前选区或清空。选中后直接修改下拉框文字，点击“保存名称”，例如“单人敌方”“群怪左侧”“图鉴编号”；名称与选区一起保存。识别过程中添加／删除会自动重新开始轮询；手动查询不会停止其他选区识别。
7. 选区、当前选择和主窗口位置默认自动保存，下次启动恢复；点击“开始识别”即可继续。选区固定在屏幕位置；移动或缩放游戏／模拟器窗口后，用调整按钮重新定位。旧版使用游戏窗口相对坐标，升级后需重新框选一次；原 `regions.txt`／`roi.txt` 保留，沿用可读取的主窗口位置。

识别最多使用两个工作线程轮询。设置中的“识别刷新率”可选每秒 0.5／1／2／4 次，默认目标每秒 1 次，自动保存；旧配置沿用默认值。按每组轮询的起始时间计时，OCR 未完成不叠加启动下一轮，实际速度受识别耗时与选区数量影响。以前的实现是在整轮结束后额外等待一秒；现在会扣除本轮耗时后再等待，避免固定等待叠加。修改刷新率不重新加载或下载模型，应用后用于下一次扫描（设置前正在扫描则自动恢复）。PP-OCR 推理线程限制为一个。

后台 OCR 和下载进程使用隐藏启动、显式重定向标准输出／错误，并设置 `STARTF_FORCEOFFFEEDBACK`，关闭 Windows 的进程启动忙碌光标。漏斗／转圈光标不能用来判断 CPU 占用；此改动控制启动反馈，不表示模型推理没有资源消耗。

自动 OCR 只把有 `No`／`#` 前缀的数字作为图鉴编号，**不会把 `Lv.29` 或裸数字 `573` 当作编号**。编号与可识别名字同时存在时交叉核对，冲突就清除提示。没有编号时匹配完整中文物种名，允许字间空格。

实时识别保留灰度笔画、4 倍双线性放大并加白边，同时尝试提取明亮、低色差的白色笔画，转为白底黑字，抑制彩色背景和阴影；白色占比过高时跳过提取。仍失败时保留 Otsu 二值化备用读法。每次只使用所选引擎，不再依赖 Tesseract。

PP-OCRv6 tiny 的官方字表包含“鼬、喵、蛹”，但仍缺少“貘、狃、鲶、聒”，涉及当前 649 个物种中的 6 个名字。不能通过预处理补上模型字表缺失的字。可使用候选确认或框选 No.编号。[字表覆盖与集成验证记录](../docs/evidence/ppocrv6-tiny-integration.json)说明了检查范围；尚未在本环境运行 Windows 实际推理，不宣称截图识别准确率已经验证。此前 Tesseract 的回归记录保留为历史证据。

若仍未识别且存在唯一的同长度、仅一个汉字不同的物种，会显示候选确认按钮。例如“君主尼”只作为“君主蛇”的候选，不会自动显示它的属性。点击确认后，仅在本次运行中记住这个读法；编号冲突不会通过候选确认自动放行。多个候选时不猜测。两次读法指向不同物种时也拒绝展示结果。

屏幕选区内名字消失、匹配冲突、截图／OCR 失败时清除旧提示。切换应用后仍会识别这些屏幕位置，不判断前台应用属于哪个游戏；需要停止时点击暂停。画面被其他窗口盖住后，只能识别当前可见内容。主窗口挡住识别区时清除该选区提示，移开或使用标题栏最小化即可。展开卡片时尽量避开所有选区；如果仍有遮挡，暂缓读取被遮挡位置，最长 15 秒未更新会清除其标签，避免将辅助窗口文字当成游戏文字。

识别状态行显示原始 OCR 结果，方便排查。只识别所选游戏语言的物种名；玩家昵称、队伍名和自定义改名暂不支持；群怪需要分别框选各自名字，不能将多个名字框在同一选区。遇到识别不到，先调整框选区域或放大游戏 UI，而不是让程序猜物种。

## 多语言

设置中的“界面语言”和“游戏语言”互相独立：

- **界面语言**：简体中文、English、日本語，控制窗口文案、按钮提示、属性卡片标题与类型名称、识别历史。应用后主窗口立即切换；设置窗口本身在下次打开时使用新语言。
- **游戏语言**：决定 Windows OCR 使用的识别语言（`zh-Hans`／`en-US`／`ja-JP`）和物种名匹配。常见组合是英文客户端配中文界面，也可以反过来。
- 首次启动（尚无配置文件）时，界面与游戏语言都跟随 Windows；已有配置保持原语言，可在设置中单独修改。

物种名和类型名称按界面语言显示；识别历史也保存为界面语言下的名称。候选确认只在同一个游戏语言内生效，切换语言后不会误用其他语言的读法。

日文 OCR 依赖 Windows 已安装的日文语言功能（设置中可打开系统语言设置）。PP-OCRv6 tiny 的字表不含假名，选择日文 + PP-OCR 时会提示只能使用 No.编号；英文使用 PP-OCR 时字母可识别，但准确率仍受模型和截图质量影响。

英文/日文名来自 PokeAPI 的公开官方译名 CSV（`en` 与 `ja-hrkt`），由 `scripts/import_species_names.py` 生成 `data/species_names.tsv`，只保留全国编号 1–649；生成后随程序离线使用，运行时不联网。来源、哈希和检查范围见 [多语言验证记录](../docs/evidence/multilingual-validation.json)。

## 识别历史

主窗口右侧的“识别历史”按时间倒序列出最近的识别结果，最多 20 条，最新的在最上面；达到上限后自动丢弃最旧的记录。

- 某个选区得到稳定物种后记录一条，包含本地时间、全国编号和物种名。同一选区连续识别同一物种不会重复新增，换物种才新增；不同选区分别记录。
- 点击列表中的记录，左侧卡片区显示该物种的完整属性；此时后续识别结果不会覆盖卡片。点击选区下拉框选择选区，或再次点击“开始识别”，即回到实时视图。
- 记录保存在 `%LOCALAPPDATA%\PokeMMOHint\recognition-history.txt`，重启后恢复。只保存物种编号、选区名称和本地时间，不保存原始 OCR 文字或玩家名称。
- 清空选区不会删除历史。历史文件缺失、损坏或版本不匹配时忽略该文件，不影响识别和选区配置。

## 数据与属性规则

- 覆盖全国编号 **1–649**，基础形态。
- 中文名来自本机中文字符串表，基础属性来自本机《黑／白1》ROM 的 personal 数据。由 `scripts/import_ocr_species.py` 提取成事实数据 TSV，未打包 ROM、图片、对话或游戏代码。不是联网从当前 PokeMMO 客户端获取的最新属性。
- 英文、日文名来自 PokeAPI 的 `pokemon_species_names.csv`（语言 `en`、`ja-hrkt`），由 `scripts/import_species_names.py` 生成 `data/species_names.tsv`，只保留 1–649 的基础物种名。类型名称的三语表内置在程序中，不来自游戏文本。
- 采用第二至第五世代的 17 属性相克表，钢仍抵抗幽灵和恶，没有妖精属性。PokeMMO 社区[属性表项目说明](https://forums.pokemmo.com/index.php?/topic/201443-pc-better-default-a-cleaner-more-polished-pokemmo-theme/)也采用这一规则；若游戏后续调整，需更新本地表。
- 计算只包含基础形态属性，不判断特性、道具、招式和对战中属性改变。洛托姆、结草贵妇等不同属性形态不能仅靠基础名称或全国编号可靠区分，本版不宣称识别实际形态。

数据提取复现（开发用，运行辅助程序不需要 ROM）：

```bash
python scripts/import_ocr_species.py --rom /mnt/d/games/PokeMMO/roms/黑白.nds --strings /mnt/d/games/PokeMMO/data/strings/z_yibu_strings_zh_dump.xml
python scripts/import_species_names.py --csv pokemon_species_names.csv --out windows-ocr/data/species_names.tsv
```

## 命令行诊断

```powershell
.\windows-ocr\target\release\pokemmo-hint.exe --text 'No.573 奇诺栗鼠' 2>&1 | Out-String
.\windows-ocr\target\release\pokemmo-hint.exe --text '523' 2>&1 | Out-String
.\windows-ocr\target\release\pokemmo-hint.exe --image 'D:\图片\敌人名字.bmp' 2>&1 | Out-String
.\windows-ocr\target\release\pokemmo-hint.exe --lang en --text 'Pikachu' 2>&1 | Out-String
.\windows-ocr\target\release\pokemmo-hint.exe --lang ja --game-lang ja --text 'ピカチュウ' 2>&1 | Out-String
```

`--lang zh|en|ja` 设置输出和默认匹配语言；`--game-lang` 单独指定匹配/图片识别语言，例如中文界面查询英文名时用 `--lang zh --game-lang en --text Charizard`。手动 `--text` 和窗口测试输入框支持裸编号。`--image` 使用设置中已应用的引擎（命令行 `--game-lang` 会覆盖图片识别语言），建议提供已经裁剪、放大的名字／编号图片；PP-OCR 图片诊断需要 32 位无压缩 BMP，Windows OCR 可读取系统支持的图片格式。实时截图模式自动生成 BMP 并预处理。GUI 程序的诊断输出建议显式重定向并等待，详见发布脚本。

程序直接截取屏幕选区，不枚举、打开或查询游戏进程，不点击游戏、不自动换人。只在按钮悬停提示中判断辅助程序自身是否位于前台。屏幕选区、名称与主窗口位置保存在 `%LOCALAPPDATA%\PokeMMOHint\screen-regions.txt`，识别历史保存在同目录的 `recognition-history.txt`，界面/游戏语言与引擎偏好保存在 `ocr-settings.txt`；旧 `regions.txt`／`roi.txt` 不覆盖、不当作屏幕坐标读取。清空选区也会保存，不会在下次启动恢复旧选区。OCR 的主／备用截图保存在程序自己的系统临时目录中，暂停／正常退出时删除；异常退出可能残留临时目录。候选确认仅保存在内存，不写入物种数据或游戏文件。

```bash

cargo check --manifest-path windows-ocr/Cargo.toml --offline --features windows-check
```

## 应用图标

图标由内置 imagegen 生成，采用精灵球、扫描放大镜与闪电元素。原图位于 `assets/app-icon.png`，Windows 图标位于 `assets/app.ico`，包含 16／24／32／48／64／128／256 像素透明图层。完整提示词和生成方式记录在 [generation.json](assets/generation.json)。

`build.rs` 自动将 ICO 写成 Windows 图标资源并嵌入 EXE，MSVC 构建不需要额外 Rust crate 或资源编译器；GNU Windows 目标需可用的 `windres`，也可通过 `WINDRES` 指定路径。程序加载同一个内嵌资源用于标题栏与任务栏。构建不需要调用生图或安装 Pillow，图标资源已包含在项目中。

工具栏图标来自一次内置 imagegen 生成的统一风格九宫格，原图为 `assets/toolbar-sheet.png`，拆分的多尺寸 ICO 在 `assets/buttons/`，完整提示词记录在 [toolbar-generation.json](assets/toolbar-generation.json)。播放／暂停图标随识别状态切换，查询与候选确认也使用同一套图标。标题栏的系统窗口按钮沿用 Windows 样式。

## 五个 ROM 的覆盖核对

已实际读取本机火红、绿宝石、心金、白金、黑白的基础属性表：火红／绿宝石各覆盖全国编号 1–386，心金／白金各为 1–493，黑白为 1–649。五者去重仍为 649 个基础物种；与应用当前表逐条对比，缺失编号和基础属性差异均为零。客户端中文基础名称也全部吻合。查看 [完整核对记录](../docs/evidence/species-coverage-audit.json)。

黑白的 personal 档案有 669 个内部记录，但包含占位和不同形态，不代表 669 个全国编号。本机中文字符串编号 150650／150651 为蛋，150657 等为洛托姆形态；这些偏移既不是全国编号，也不能直接与 ROM 中同索引的记录对应。全国编号与基础种类完整不等于所有形态已覆盖，或这些物种在 PokeMMO 都可捕获。

目前尚未分别查询的属性变化形态包括洛托姆家电、结草贵妇蓑衣、谢米天空形态、达摩狒狒达摩模式、飘浮泡泡天气形态、美洛耶塔舞步形态等；只凭基础名或编号无法可靠区分。该限制仍存在，本次没有把它们错误追加为全国编号 650 以后。

复现核对：

```bash
python scripts/audit_ocr_coverage.py --rom-dir /mnt/d/games/PokeMMO/roms --strings /mnt/d/games/PokeMMO/data/strings/z_yibu_strings_zh_dump.xml
```

PokeMMO 对 ROM 的官方用途说明见 [Installing The Game](https://support.pokemmo.com/knowledgebase/article/installing-the-game) 和 [Importing Or Changing ROMs](https://support.pokemmo.com/knowledgebase/article/importing-or-changing-roms)。以上物种数量来自本机实际解析，不把社区建议帖当成已上线的游戏功能。

## 发版与用户安装

在 Windows 仓库根目录执行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\release_windows.ps1
```

输出为 `dist/PokeMMO-Hint-v版本-windows-x64.zip` 及 `.zip.sha256`。发给用户的是这两个文件；用户解压 ZIP 后双击 `pokemmo-hint.exe`，不需要 Rust；基础包不包含模型／额外引擎。Windows 中文 OCR 使用系统功能，PP-OCR 在设置中按需下载，之后离线使用。详见 [发布流程](../docs/releasing.md)。

设置齿轮与配套图标由 imagegen 生成，风格沿用现有工具栏。[提示词和资源记录](assets/settings-generation.json)。
